## 3. Code-level changes (modified cells)

### 3.1 `curate_df` (cell 12) — binary-aware missing detection

**File:** [exploring_2.ipynb](exploring_2.ipynb) cell 12 (was OLD cell 6).
**Delta:** 1,176 → 2,977 chars.

Before: `missing_ratio = df.isna().sum() / len(df)` — pure NaN ratio. A `0`
in `is_orientation_north` (meaning "does not face north") and a `0` in
`n_rooms` (suspicious data) were treated the same way: not missing at all.

After:

- New helper `_is_binary(s)` flags columns whose dtype is `bool` or whose
  non-null values are a subset of `{0, 1, True, False}`.
- For **non-binary** columns, the missing mask becomes `isna OR (== 0)`.
- For **binary** columns, only NaN counts as missing — so `is_orientation_*`,
  `has_*`, `is_*` flags are protected and survive even at
  `missing_threshold=0.75`.
- Prints the protected binary list so the user can sanity-check the
  auto-classification.

**Downstream effect:** `parking_price` (high zero ratio) now gets dropped
automatically — which retired the manual workaround in old cell 32 (see §5).

### 3.2 `COLS_TO_DROP_FINAL` (cell 9) — rent-side leakage added

**File:** [exploring_2.ipynb](exploring_2.ipynb) cell 9 (was OLD cell 4).
**Delta:** 793 → 972 chars.

Old list dropped only buy-price-derived leakage:

New list also drops the rent-price equivalents, which would leak via

Minor cleanup: stray trailing `#` comments removed from a few amenity flags.

### 3.3 §3.5 Overfitting diagnostics (cell 45) — Fig 3 expansion

**File:** [exploring_2.ipynb](exploring_2.ipynb) cell 45 (was OLD cell 30).
**Delta:** 13,684 → 16,065 chars. +102 lines added, −56 removed.

The single biggest code change in the diff. What changed:

**Refactor:**
- New helpers `_cv_curve(model_cls, base_params, param_name, values)` and
  `_plot_vc(ax, xs, tr, cv, ...)` factor out the panel-fitting and
  panel-drawing logic. The old version had three near-duplicate inline
  blocks.

**Fig 3 grew from 2 panels to a 2×2 grid:**
| Panel | Sweep                                     | Status     |
|-------|-------------------------------------------|------------|
| (a)   | `DecisionTreeRegressor.max_depth`         | unchanged  |
| (b)   | `RandomForestRegressor.min_samples_leaf`  | **now log-scale x-axis** (was linear and visually squashed) |
| (c)   | `RandomForestRegressor.max_features`      | **new panel** — the meaningful bias-variance knob for RF on tabular regression |
| (d)   | `RandomForestRegressor.max_depth`         | **new panel** — bounded depth as a cleaner complexity knob |

Rationale (in the markdown for cell 44): the old `min_samples_leaf` panel
produced a monotone CV curve, which means the knob is not trading bias for
variance — it is just shrinking the model uniformly. RandomForest already
controls variance through bagging, so the parameters that actually drive a
meaningful bias-variance trade-off are `max_features` and `max_depth`.

**Robustness fixes (Python 3.14 quirks):**
- Added `warnings.filterwarnings("ignore", message=r".*sklearn\.utils\.parallel\.delayed.*")`
  to silence dozens of benign `UserWarning`s from sklearn's joblib parallel
  on Python 3.14.
- Replaced `plt.show()` with `fig.savefig(...)` + `IPython.display.Image(...)`
  because matplotlib's inline backend can silently fail on Python 3.14;
  saving to disk and re-reading is backend-agnostic.

**Euro-scale scorers added:** `_mae_euros`, `_medae_euros`, `_mape_euros`
back-transform log predictions before scoring, so the reported MAE / MedAE
/ MAPE are in euros / percent — the only interpretable units.

## 4. Entirely new code cells

### 4.1 §3.6 Paired t-test (cell 49) — NEW
**File:** [exploring_2.ipynb](exploring_2.ipynb) cells 48 (markdown) + 49 (code).
**Size:** ~3.7 kB code + ~1.1 kB markdown. No equivalent in OLD.

**Question it answers:** the §3.4 CV means tell us *which* model has the
lowest MAE on average, but not whether any difference is statistically
meaningful given fold-to-fold noise.

**How:**
- 10-fold `KFold(shuffle=True, random_state=42)` — **identical splits across
  every model** (required for paired-t validity).
- Models compared: `DecisionTreeRegressor`, `RandomForestRegressor`,
  `XGBRegressor`, `LGBMRegressor`.
- Euro-scale MAE scorer.
- Per-fold MAE matrix printed; summary mean+std table.
- Pairwise `scipy.stats.ttest_rel` for all 6 pairs, with significance
  markers (`***` p<0.001, `**` p<0.01, `*` p<0.05, `ns` otherwise).
- Box+strip plot of per-fold MAE per model → `fig_model_comparison_paired_ttest.png`.

**Caveat documented in the markdown:** classical paired t-tests on k-fold
CV have inflated Type I error because training folds overlap. Treat
p ≈ 0.05 cautiously; p < 0.001 is robust to the caveat. Nadeau–Bengio
correction is mentioned as the formal fix but not implemented.

## 9. Known issues identified during the restructure (open)

These were surfaced while writing this changelog and are not in the v2
notebook yet:

- **`encode_neighborhood` (cell 23) is dead code.** `run_pipeline` (cell 24)
  calls `prepare()` (cell 22) but never `encode_neighborhood`. The richer
  parser that extracts `neighborhood_price_m2`, `neighborhood_rank`,
  `district_<name>_*` exists in the notebook but is unreachable. The
  pipeline's neighborhood handling lives inline in `prepare`, which only
  extracts integer IDs.
- **Nested `n_jobs=-1` in §3.5 cell 45 panels (b)/(c)/(d).** Outer
  `cross_validate(n_jobs=-1)` × inner `RandomForestRegressor(n_jobs=-1)`
  spawns nested parallel workers and can crash the kernel on Python 3.14
  / WSL. Single-level parallelism needed (drop the inner `n_jobs=-1`).
- **§5 Conclusion body is a placeholder** — header in cell 64, no real
  content yet.

## 10. Method note

This changelog was produced by:
1. Loading both notebooks via `json.load`.
2. Building the set of code-cell sources from each and computing the
   symmetric difference (new cells, removed cells).
3. For each unmatched NEW cell, hunting for a best-effort OLD counterpart
   by section position and diffing them line-by-line.
4. Verifying every OLD code cell has either a matching NEW cell (exact or
   near-exact) or a documented reason for removal.

Run `python -c "import json; ..." ` against both files to reproduce.
